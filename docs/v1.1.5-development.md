# v1.1.5 development (unreleased)

This branch accumulates v1.1.5 beta candidates. **Do not install on a production alarm panel before tests and hardware validation.**

## Work completed on this branch
- Legacy FlexC CONNECT ACK now echoes the SPC account code instead of a captured constant.
- An incoming replacement TCP session immediately fails the previous in-flight command.
- Stale command timeouts cannot close a newer TCP session.
- Reader ignores buffered frames belonging to a superseded connection.
- TCP sessions inactive for 60 seconds are closed (including incomplete-frame reads).
- Bundled card resource cache marker updated to 1.0.19, per the HACS review.
- Regression tests added for account echo, session replacement, stale timeout, and idle connection.
- CI now checks this development branch on push, including Ruff, mypy, pytest and coverage.
- SPC transport error 54 is now a dedicated `FlexCAuthenticationError`; other codes retain their numeric identity, with regression tests.
- Non-blocking, per-TCP-session identity change diagnostics and regression tests added.

## Beta.2 diagnostics in development
- Record one sanitized identity sample per incoming message type and TCP session (CONNECT, EVENT, POLL, DATA, etc.), without logging frame payloads or secrets.
- Recognize the known receiver-side connection ID `0x77359401` as an informational identity difference rather than a warning; retain warnings for other unexpected differences. This is provisional until more hardware observations are available.
- Explicitly observe `KEY_UPDATE` (`0x40`) and `KEY_ACK` (`0x41`) without responding, changing keys, or logging key material. A frame that cannot be decoded cannot be classified by message ID.
- Added regression tests for identity sampling, receiver connection ID and key-management observation. Hardware validation is pending.

## Still to investigate (issue #11)
- Session identity diagnostics now establish a baseline on CONNECT and warn once per changed account, connection ID, or receiver identifier, without rejecting traffic. Confirm which identifiers remain stable on real panels before enabling strict validation.
- FLEXC key update 0x40 / 0x41 semantics remain unverified. Henrik's implementation sends a KEY_ACK without rotating its AES key and explicitly notes that no real-panel KEY_UPDATE was observed. Do not copy this ACK as evidence of automatic encryption or key rotation support. Continue using the verified **Fixed Encryption** mode and the same 64-hex-character AES-256 key on the panel and in Home Assistant. Automatic encryption modes are not validated; do not silently acknowledge a key change that cannot be applied.
- Decide whether and how `FlexCAuthenticationError` should trigger Home Assistant reauthentication; do not change the config-entry state without a verified panel scenario.
- Double-check that the 60-second idle threshold is safe across panel firmware and configuration differences.
- Strengthen race tests for an old reader finishing after replacement, and for command/reconnect ordering.

## Authentication notes from Henrik (SPC firmware 3.14.1)
- Reported FlexC username length: **4–16** characters; web password length: **6–16** characters. The panel web UI may accept a longer password while FlexC rejects it with error **54**.
- Reported allowed characters: ASCII letters, digits, and `. ! @ # $ % _ + - = ; < > ?`.
- If panel-user credentials still yield error 54, check **Communications → FlexC → ATS Command Profile** and its **Command User or Panel User** setting. The command profile may use separate credentials.
- These are firmware-specific observations, not yet enforced globally in the integration.
- Setup reference: [Henrik’s illustrated panel setup guide](https://github.com/henrikekblad/spc-flexc-home-assistant/blob/main/docs/panel-setup.md) (MIT licensed; credit retained).

## Real-panel validation checklist (before merge)
- Confirm a normal connection and POLL traffic with **Fixed Encryption**, then exercise a status refresh and a command.
- Observe at least one reconnect (panel-initiated if possible) and confirm no old command response or timeout affects the new TCP session.
- Inspect logs for `identity changed` warnings, noting the message type and field; do not enable strict identity checks before determining legitimate field changes.
- Confirm no unexpected idle disconnects during normal panel activity; reassess the 60-second threshold if firmware sends polls less often.
- If error 54 can be reproduced safely, confirm it is reported as authentication-related; do not intentionally alter production credentials solely for testing.
- Leave **Automatic Encryption** and **Automatic Encryption with Rotation** untested/unsupported until protocol behavior can be captured and implemented safely.

Run `make check` and `make coverage` (Python 3.14); see GitHub Actions for authoritative results. Do not claim a fix is field-proven before testing against a real SPC panel.
